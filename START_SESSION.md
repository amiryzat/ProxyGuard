
# Start Session

Before writing or modifying any code:

Read the following in order:

1. Read [[CLAUDE]] (`CLAUDE.md`) completely.
2. Read [[project-overview]] (`docs/project-overview.md`).
3. Read [[roadmap]] (`docs/roadmap.md`).
4. Read any other documentation relevant to the task.`

Only read additional documentation when it is relevant to the task.

## Development Rules

- Understand the existing implementation before making changes.
- Do not rewrite working code unless necessary.
- Keep the existing project structure.
- Explain major changes before implementing them.
- Update the documentation after completing a feature or fixing an important bug.
- Update `docs/project-overview.md` if the project purpose, scope, users, objectives, or tech stack changes.
- Update `docs/architecture.md` if the system flow, module structure, data flow, or major design changes.

##  Documentation Rules

- Update `docs/roadmap.md` when project progress changes.
- Update `docs/decisions.md` when an important design decision is made.
- Update `CLAUDE.md` only if the project's core architecture or permanent rules change.
- Update `docs/project-overview.md` if the project purpose, scope, users, objectives, or tech stack changes.
- Update `docs/architecture.md` if the system flow, module structure, data flow, or major design changes.

## End of Task

Before finishing a task:

- Update `docs/roadmap.md` if progress changed.
- Update `docs/decisions.md` if an important technical decision was made.
- Update `docs/testing.md` if testing was performed.
- Update `docs/bugs.md` if an important bug was fixed or documented.
- Update `docs/project-overview.md` if the project purpose, scope, users, objectives, or tech stack changed.
- Update `docs/architecture.md` if the system flow, module structure, data flow, or major design changed.
- If no documentation changes are needed, state why.
